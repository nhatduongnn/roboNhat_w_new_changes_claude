RoboCOP + Fiber-seq · posterior fix · 2026-10-20

FiberCOP C1 Check

Does the backward-pass bug C1 fire in FiberCOP, and where? Yes. It fires in every model we tested, on chromosomes with ordinary coverage, through a route the MNase check cannot see.

Answer. We ran the original C code and the audit's C1-fixed C code on the same inputs for every segment of the nuclear genome, for three models.

  • bo09 r48: 122,382 posterior rows broken by C1, in 217 of 3,021 segments, on all 16 chromosomes.
  • bv75 r49: 17,689 rows in 59 segments; 13,794 of them in rDNA.
  • bu01 r11: 13,798 rows, all in the chrXII rDNA array. Clean everywhere else.

These are rows of the original decoder, the one that produced every bo09, bu01 and bv75 decode and the viewer tracks.

What C1 is

The backward pass builds its silent states before rescaling the row

RoboCOP's HMM has silent states: junctions between features (a TF, a nucleosome, background) that emit nothing. In the backward pass, bward (pkg/robocop/algo.c:185-198) fills the silent states of a row from the row's emitting cells before the row is rescaled. The audit's fix moves the rescale first. That one reordering is the only difference between the two C libraries compared here.

Why the MNase check does not carry over

The emission bound says “safe” exactly where C1 fired

For MNase, C1 was ruled out with a bound: the best emission at position t times the best at t+1 must stay above the smallest double, 2.2×10−308. On the real bo09 event at chrXIV:413,386 that bound is nowhere near the line:

The mechanism in FiberCOP

DBL_MIN padding on silent cells, divided by a tiny row sum

  1. normalize() (algo.c:10-30) adds DBL_MIN (2.2×10−308) to every cell of the row, silent cells included, then divides the whole row by the emitting sum S.
  2. Because the original code fills silent cells before that step, they are still S times too small. The padding swamps them: every silent cell becomes DBL_MIN / S (all 155 of 155 silent cells at the row before the event).
  3. With MNase, S is about 10−2, so the fake mass is about 10−306 and harmless. With Fiber-seq, the 1×10−30 floor on each unscored strand makes S between 10−31 and 10−99, so the fake mass is 10−277 to 10−209 per row.
  4. The fake mass does damage where a later row's real mass falls below it. At 413,386 the true emitting sum is 1.07×10−99; the fake mass wins and rescales every position upstream of it.

Proof, from a numpy replay of both backward passes that reproduces the C tables to within 10−14:

backward passscale at 413,386
original C code1.097×10−86
original order, silent-cell padding removed1.069×10−99
C1-fixed C code1.068×10−99

So no bound on emissions alone can stand in for running the recursion: the trigger depends on the floors, the masks, the tuned priors (down to 1.4×10−51 in bo09) and the recursion itself.

Method

Run both C libraries on every segment

c1scan/scan_genome.py, one Slurm array of 48 tasks per model (jobs 13070845, 13070895, 13070896; all 144 tasks completed). For each of the 3,021 windows in coord_genome_full.tsv (5 kb, stepping 4 kb, chrI–chrXVI end to end; chrM is not in the file):

  • Build the emission and transition matrices with that model's own package copy and trainDir, by the real decode pipeline, stopping just before its C step.
  • Run the forward pass once, then the backward pass and posterior twice: librobocop_prenorm.so (md5 6a0724bf, the original) and the audit's librobocop_fixed.so (md5 6dbd5e6d, C1 fixed).
  • A C1 row is a position whose posterior row sum is off by more than 10−4 with the original library and correct with the fixed one. Rows wrong under both are counted separately as “not C1”.

Limits

What this check does not cover

  • chrM is not covered (not in the genome coordinate file).
  • bo09 chrVI:208,001–213,000 has 2,763 rows wrong under both libraries, so not C1. The cause is not established.
  • The C1-fixed library is a way to assign blame, not ground truth: it keeps the DBL_MIN padding in the forward pass.
  • Production fix B renormalises every row, which hides C1. On segment 307 that brought it within 4.8×10−9 of log space; other segments are unverified.
