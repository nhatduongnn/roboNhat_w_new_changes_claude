Brute force: add up every path

All 136 hidden paths through the 6 positions, each with its own probability (kept as a logarithm, so 10−321 is just −321). A table entry is the sum over the paths it covers.

Tables are laid out like the C arrays: one row per position and one column per state (table[I(i, j, n_states)]). btable is stored upside down: row 0 holds the last position (t=5), and the code reads it back with Ir(). So the backward pass fills these tables top to bottom. Column names: BG background, F1/F2 TF1 forward, R1/R2 TF1 reverse, N1–N4 nucleosome (N3a/N3b are the two branch states), then the silent states CENTRAL and TF-entry.

Brute force, from scratch · ordinary walkthrough data

How likely is this data, and which state made each base?

This tab uses the walkthrough's normal example (sequence , ordinary fragment counts), so every number stays readable. The model doesn't know which state produced each base. Brute force answers the question the slow, obvious way: write down every possible explanation, work out how likely each one is, and add them up.

Step 1

One explanation, multiplied out

An explanation (a hidden path) picks one state for each of the 6 bases, plus the junctions it passes through. Its probability is a long product: where it starts, every move between states, and how likely each state is to produce its base and read counts. Here is the most likely of all the paths, one factor per row:

Step 2

Every explanation, and their total

Do the same multiplication for every path the model allows. With these 6 bases there are paths with non-zero probability. Adding all of them up gives the probability of the data itself, P.

Step 3

Answering the question: the posterior

"How likely is it that state j produced base t?" = (total of the paths that have j at t) ÷ P. Each row adds to 1, because every path has exactly one state at each position. This table is exactly what RoboCOP outputs. Click a cell to list its paths in Step 2.

Forward = the sum of all beginnings, built left to right

The forward value f[t, j] is exactly the sum of all beginnings that end with state j at position t. It never lists them. It reuses the previous position's sums, because every beginning at t is a beginning at t−1 plus one more step:

Backward = the sum of all endings, built right to left

The backward value b[t, j] is the sum of all endings after state j at position t, built from the next position's sums. The table is shown in btable's stored order, last position first:

Step 7

Forward × backward gives the same answer as brute force

So forward and backward compute the brute-force answer exactly, without ever listing a path.

Step 8

Why not just use brute force?

The number of paths explodes with the length of the sequence. Forward and backward only touch each of the model's transitions once per position.

Path counts are for this 12-state toy model, ignoring which paths the data rules out. The real RoboCOP model has hundreds to thousands of states, so its counts are far larger still.

Step 9

Why the code rescales, and where C1 comes in

The forward sums shrink at every position: each row adds up to the probability of the data so far.

For a 5,000-base segment that number is around 10−31,558, far below the smallest double (about 10−308). So the C code divides every row by its sum (sf[t] forward, sb[t] backward) and keeps only the ratios. Multiplying the stored f̂ back by sf[0]·…·sf[t] gives the textbook forward values above to within .

C1 is a slip in that rescaling bookkeeping in the backward pass: the silent states are computed before their row is rescaled, so two tiny emissions are multiplied together first.

Forward · fward

f[t, j]: how did we get here?

1 · The question

The probability of the data from base 0 up to base t, with state j producing base t.

2 · The equation
f[t, j] = Σp f[t−1, p] · T(p→j) · et(j)

Add up every previous state p that can lead into j: be in p at base t−1, move to j, and j emits base t.

3 · Pull the emission out

et(j) depends only on j and base t, not on p. It's the same number in every term, so it factors out of the sum (a·x + b·x = (a + b)·x):

f[t, j] = et(j) · Σp f[t−1, p] · T(p→j)
4 · In the C code

Line 82 builds the sum (+=) of previous value × transition. Lines 84-85 then multiply the finished sum by the emission once (all 5 data layers).

Backward · bward

b[t, j]: how likely is what comes next?

1 · The question

The probability of the data from base t+1 to the end, given that state j produced base t.

2 · The equation
b[t, j] = Σc T(j→c) · et+1(c) · b[t+1, c]

Add up every next state c that j can move to: move to c, c emits base t+1, then everything after that.

3 · Can the emission come out? No

The emission here is the next state's, et+1(c). It changes with c, so it's a different number in each term. There's no common factor to pull out, so it stays inside the sum:

b[t, j] = Σc T(j→c) · et+1(c) · b[t+1, c] (unchanged)

State j's own emission of base t isn't in b at all. It's already in f[t, j], so f × b counts base t exactly once.

4 · In the C code

Line 175 computes the emission again for every child (emissionValues), and lines 176-179 multiply it into that child's term before adding. Silent states (lines 188-195) work the same way, with the children's emission of base t.

Two outputs per segment
