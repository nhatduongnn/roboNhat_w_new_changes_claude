Five decoders, two truths

Which ones match brute force on Fiber-seq data?

Same 12-state toy model as the other tabs, sequence AATTAA, but the data are Fiber-seq m6A counts: at each base, n reads cover the scored strand and k of them are methylated. Each state's emission is Binom(k; n, p) with that state's fitted methylation probability p.

methodwhat it is
original RoboCOPfiberCOP's original algo.c (librobocop_prenorm.so), floored emission.
fix B (production)Today's librobocop.so: rescales each posterior row to sum to 1. Its backward pass is the original one, so C1 is still in it.
C1 fix (audit)The audit's librobocop_fixed.so: rescales each row's emitting cells before computing its silent cells.
log space, floored emissionThe fork's log-space decoder, fed the log of the same floored emission. No underflow anywhere, but the input is already wrong.
log space, exact emissionSame decoder fed the exact binom.logpmf (ROBOCOP_LOG_EMISSION=exact). No floor.
truth: floored modelBrute force (every path added up, in logs) on the floored emission: the right answer for the model production actually builds.
truth: exact modelBrute force on the exact emission: the right answer for the real data.

Floor = when binom.pmf underflows to 0 (too small for a double), production replaces it with a fixed small number. That number can be far larger than the true value, so it can flip which state the data favour.
