H7

Part 1 The decoder

What changed

Same models, same reads. Only the arithmetic inside the decoder is new.

Before · original decoder

  • Multiplies thousands of tiny probabilities, rescaling as it goes.
  • The undo step left a leftover factor: some rows summed far above 1 (bo09 up to 3.6 × 1060).
  • The viewer clipped each value to [0, 1] and averaged overlapping segments, so a broken row could show up as 0.50 or 1.00.
  • Adds a tiny number (DBL_MIN, 2.2 × 10-308) to every cell to avoid dividing by zero. Sometimes that fake mass wins.

After · log space

  • Adds logarithms instead of multiplying tiny numbers. Nothing underflows.
  • No leftover factor: every row sums to 1 (largest row sum 1.00000000000005).
  • No DBL_MIN padding. An impossible position stops the run with an error instead.
  • Emissions computed exactly; no 10-30 floor.

H1

Part 1 Detail · the C1 bug

C1: the backward pass builds silent cells before rescaling

normalize() adds DBL_MIN to every cell, then divides the row by its emitting sum S. The original backward pass computes the silent cells first, so they are S times too small and the padding swamps them.

Where it bites. With the 10-30 emission floor, S is 10-31 to 10-99, so the fake mass per row is 10-277 to 10-209. It does damage where a later row's true mass falls below it.

One example. bo09, chrXIV segment 412,001–417,000: the original and the C1-fixed backward pass differ at one position (413,386), by 29.96 nats — the 1.03 × 1013 row-sum step.

With MNase, S is about 10-2 and the fake mass about 10-306: harmless.

Part 2 single-fiberCOP · implementation

How single-fiberCOP works

The same RoboCOP model, run on one Fiber-seq read at a time.

  1. 1

    Load the HMM

    RoboCOP log-space decoder, 3,485 states: background, 154 TFs × forward + reverse, and a 531-state nucleosome.

  2. 2

    Read each read from the BAM

    m6A probability per A, called methylated (p ≥ 0.81), unmethylated (p ≤ 0.19) or no-call.

    0.81 = modkit's automatic threshold (ML ≥ 207 of 255).

    Forward read: Watson A's. Reverse read: Crick A's (stored as T).

  3. 3

    Place calls on the reference

    Each call goes to its sacCer3 coordinate. The sequence layer uses the reference genome.

  4. 4

    Emission: score each base, each state

    log PWM(base)
    + log p(m6A) if methylated
    + log(1−p) if unmethylated

    One Bernoulli per A. No-calls add 0.

  5. 5

    Forward–backward, in log space

    Gives a per-base posterior for every state, on that one read.

Works · nucleosomes per read

Chereji ±1 dyads: 4 of 4 within 20 bp.

Does not work · TF calls per read

ABF1's prior is 1.8 × 10-7 per bp, and one read gives about 5 informative A's in the 14 bp motif.

Part 2 single-fiberCOP · what we checked

Five problems we found

ProblemWhat it isWhat we foundFix
1Decoding direction Crick reads were decoded 3'→5'. Each read can now be decoded 5'→3' on its own strand. Done: new driver.
2Same answer both ways One read should give the same answer in either direction. "Start anywhere" fixes the read ends, but a gap of about 0.2 remains. The gap comes from the sequence layer → fix 3.
3Nucleosome model asymmetry It scores a sequence and its reverse complement differently. It was trained on one strand only, and its m6A profile is 1 bp off centre. Planned: retrain on both strands; refit m6A 1 bp left.
4Reference vs read sequence Should each read use its own bases? Read differences are mostly nanopore errors, not real variants. Use the reference unless ≥ 10 reads and > 50% agree on another base.
5TF start chance too low ABF1 is entered with a chance of 1.8 × 10-7 per bp. Even a perfectly protected fake read only reaches ABF1 ≈ 5 × 10-6. Next: a per-site prior (fraction of reads bound) instead.

Details on hidden slides H5 (numbers, incl. the fake-read test) and H6 (the 1 bp offset). Code in analysis/singlefiber/.

Part 2 single-fiberCOP · detail

Five problems we found

ProblemWhat it isWhat we foundStatus / fix
1Decoding direction Every read was decoded left→right on the reference, so Crick reads ran 3'→5'. New driver decodes each read 5'→3' on its own strand: Crick reads are reverse-complemented, decoded, then mapped back. --direction ref reproduces the old driver exactly (0 of 44 outputs differ). Done. run_permol_window_logfull_5to3.py
2Same answer both ways One read should give the same answer decoded in either direction. 100 reads at ERV46, largest difference per read (median / max): today's start rule 0.75 / 0.97; start anywhere 0.21 / 0.39; sequence layer off 6 × 10-8 (exact). Start anywhere fixes the read ends. The rest comes from the sequence layer, most likely the nucleosome model (not yet isolated). Built (--start any). Remaining gap → problem 3.
3Nucleosome model is not symmetric It scores a sequence and its reverse complement differently: 0.40 log10 on average. Its sequence part was trained on a random, unseeded draw of 5,000 of 9,271 Chereji dyads, Watson strand only (calc_dinucleotide.py:135, 147-149). All 9,271 + reverse complements cuts it to 0.04. Also, the m6A profile was fit 1 bp off centre (next slides). Planned: symmetric retrain + recentred m6A fit.
4Reference or read sequence? Should the sequence layer use each read's own bases? Read differences are mostly nanopore errors, not variants: 0 positions at ERV46 where ≥ 50% of reads disagree; strand-specific hotspots; a systematic G error in "CGA". Using read sequence moved nucleosome calls by up to 0.65; one error in a motif cut ABF1 100–1000×. Use the reference, unless ≥ 10 reads cover a base and > 50% agree on another (consensus_seq.py; 0 changes at ERV46).
5TF start chance too low ABF1's start chance is 1.8 × 10-7 per bp; one read has only 4–5 informative A's in the motif. Fake reads at ERV46 site 1, real decoder: no calls 3.3 × 10-6; motif fully protected 4.9 × 10-6 (best); motif methylated 1.2 × 10-7. 0.5 needs a ~105× higher start chance. Next: per-site mixture model; fraction bound f from all reads replaces the 1.8 × 10-7.

ERV46 window: chrI:60,001–65,000. Code in analysis/singlefiber/. Problem 2 numbers: permol_proto_logfull/dirtest100/summary.json (next slide). Problem 5: fake-read test, 26 Oct (its scratch files were lost in a /tmp wipe; numbers recorded in this session, rerun to regenerate).

Part 2 single-fiberCOP · problem 3 in detail

The m6A nucleosome profile is 1 bp off

Both nucleosome fits read the same Chereji dyads but put the centre on different bases.

Two centres for one dyad

A Chereji row is 1 bp wide, e.g. chrI 2386 2387.

  • Sequence model: centred on base 2386 (calc_dinucleotide.py:131, 147-148).
  • m6A fit: centred on base 2387 (abf1_reb1_dms_parameter_Fiber-seq_w_binom.py:951-953).

The m6A fit is the one that is off

A nucleosome's Watson m6A profile should mirror its Crick profile about the true centre.
